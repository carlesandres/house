## Dependency notes

- Plan 001 implements the behavior-neutral component extraction approved by
  [issue #66](https://github.com/carlesandres/house/issues/66). It creates a stable rendering seam
  without moving filtering, selection, discovery, or keyboard behavior.
- Plan 002 deliberately remains separate because it changes state ownership, fixes selected-file
  identity during streamed reranking, adds a workspace package, and changes the release build.
  [Issue #235](https://github.com/carlesandres/house/issues/235) approves that broader scope.
- Plan 002 began from Plan 001's completed component boundary; the two plans remained separate.
- Plan 002 was implemented in isolated branch `advisor/002-extract-file-navigator`; its initial advisor
  review found two high-risk hook defects after the maximum two executor revision rounds. Plan 003
  repaired both defects and passed executor plus independent advisor review at `f252e47`.
- Plans 002-003 were delivered through PR #237. Their preserved implementation hashes differ from the
  final cherry-picked hashes, but `e7655ac` is the authoritative merge baseline.
- Plans 004-007 implement the filesystem-aware component designed in
  [`docs/file-navigator-design.md`](../docs/file-navigator-design.md). They are split into independently
  green feasibility, presentation, core, and migration PRs.
- The File Navigator sequence was approved in the design session. A GitHub tracking issue is optional
  bookkeeping, not an execution prerequisite. Backend adoption still requires approved feasibility
  evidence.
- Plan 004 rejected Chokidar 5.0.0 after Bun 1.3.10/darwin-arm64 reproducibly crashed in the required
  10,000-file broad event-mode benchmark. Chokidar remains rejected.
- Plan 004B initially rejected Parcel Watcher 2.6.0 under the physical-watch-pruning requirement. The
  design session then relaxed that requirement: Discovery Scope strictly limits scanner membership,
  but the native backend may observe a broader root. Parcel passed all four target correctness/repeat
  and generated-static standalone gates, plus the required native stress evidence. The project owner
  explicitly approved Parcel 2.6.0 and the Linux 60-second consistency policy on 2026-08-01, unblocking
  Plans 005-007.

## Decision history

- **Put House's fuzzy ranking in `@house/ui` as the default:** still rejected. Plans 004-007 instead
  use an independent fuzzysort-backed default and let House adopt that behavior without compatibility
  bonuses.
- **Add generic order/search strategy boundaries:** previously rejected before a second requirement
  existed; now accepted by the filesystem-aware design, with built-in tree/recent and fuzzy behavior.
- **Move `PromptRow` into `@house/ui`:** rejected. It is shared with the House command palette and
  carries product-specific prompt styling. House passes it as a header slot.
- **Publish `@house/ui`:** rejected. The package remains private and is bundled into House.
- **Adopt scoped keymap composition:** rejected. `DESIGN.md` §12 still defers that pattern; Browser
  remains the only `useKeyboard` owner.
- **Redo Plan 002 from merged `main`:** rejected. The isolated implementation already passes all
  functional, packaging, and release gates; a focused controller repair preserves that validated work.
